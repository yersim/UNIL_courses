Decision tree: We are now going to build a decision tree to predict the species a given iris plant (represented by the four measurements Sepal Width, Sepal Length, Petal Length, Petal Width) belongs to. Try to go through all the steps and to understand what each step is doing.

Let us set the seed to some value to make the whole analysis reproducible, and split the Iris dataset into a training set, a validation set and a test set:

seed=530
data(iris)

set.seed(seed)
ind=sample(3,nrow(iris),replace=TRUE,prob=c(0.60,0.20, 0.20))

iris.training=iris[ind==1,]
iris.validation=iris[ind==2,]
iris.test=iris[ind==3,]

Make the decision tree model using the entropy as the impurity index, and (minsplit=10, minbucket=5) as stopping rules:

set.seed(seed)
decision_tree=rpart(data=iris.training,Species~Sepal.Width+Sepal.Length+Petal.Length+Petal.Width,method="class",control=rpart.control(minsplit=10,minbucket=5),parms=list(split="information"))

Here the seed variable controls the internal random generator that is used by the decision tree algorithm (for example for selecting one of the best questions if there are several questions with the same largest information gain).

Above we used (minsplit=10, minbucket=5) as stopping rules. Let us now use the cost complexity pruning method instead to find the best tree:

set.seed(seed)
decision_tree=rpart(data=iris.training,Species~Sepal.Width+Sepal.Length+Petal.Length+Petal.Width,method="class",control=rpart.control(minsplit=1,minbucket=1,cp=0),parms=list(split="information"))
rpart.plot(decision_tree,main="The Biggest Tree",extra=101)

This is the biggest tree possible. We now need to prune this tree up to the smallest cross-validation error:

printcp(decision_tree)

Here “cp” is the minimum of the cost complexity pruning parameter, that was written as alpha in the lectures, for which the pruning happens, “nsplit” is the number of splits (or questions) that are present in the pruned tree, and “xerror” is the validation error associated to the pruned tree. As we have seen in the lectures, the cp values control the size of the tree (a greater cp value implies fewer questions in the tree).

Let us make some plots of this table:

plot(decision_tree$cptable[,"CP"],decision_tree$cptable[,"xerror"],type="S",xlab="CP",ylab="xerror")

plot(decision_tree$cptable[,"CP"],decision_tree$cptable[,"nsplit"],type="S",xlab="CP",ylab="nsplit")

Comment: To be more precise, the program uses K-fold cross-validation (with K=10) to compute the cross-validation error “xerror” and its standard deviation “xstd”. This method divides the training dataset into K folds, where K-1 folds are used as training and the remaining Kth fold is used as validation. The cross-validation error is obtained as the average error on the data in the left-out Kth fold.

From this table, we can select the cp value associated to the lowest validation error (cp=0.016667) and use it to prune the tree in an optimal way:

cp_best=decision_tree$cptable[which.min(decision_tree$cptable[,"xerror"]),"CP"]
print(cp_best)
## [1] 0.01666667

Comment: In cases where a small change in cp implies a large change in nplits, you may use the “1SE rule”. This rule says that you should look for the minimum of xerror but then go up 1SE (given by “xstd”) because that tree will be less complex. For example, that would suggest selecting a tree (an upper row with fewer splits) associated to the xerror = 0.10000 + 1 * 0.0394410 = 0.139441. This is not the case for the Iris dataset.

Comment: There is another equivalent way to choose cp, which consists basically at looking at an “average plot” version of the above table:

plotcp(decision_tree)

The vertical axis “X-val Relative Error” corresponds to “xerror” in the previous table. There is a subtlety for the horizontal axis. Indeed the cp values shown in the plot are actually the geometric means of two consecutive cp values in the table above: cp_plot_n = sqrt(cp_table_n * cp_table_n-1), with n = 1, 2, 3, 4, 5 and cp_table_0 = infinity or Inf. For example, cp_plot_3 = sqrt(0.016667*0.433333) = 0.085. From this plot, we would choose the best cp as 0.085. Looking at the previous plots “xerror” versus “CP” and “nsplit” versus “CP”, we see that all the values of cp in the interval [0.016667, 0.433333[ give the same pruned tree (nsplit=2), and thus cp=0.085 (the geometic mean of 0.016667 and 0.433333) leads to the same pruned tree as with cp_best = 0.016667. Let me remind you that the “size of tree” is defined as the number of leaves in the tree. The horizontal line is drawn 1SE above the minimum of the curve.

pruned_tree=prune(decision_tree,cp=cp_best)
rpart.plot(pruned_tree,main="Pruned Tree",extra=101)

We see that we obtain the same tree as with (minsplit=10, minbucket=5) as stopping rules.

Random forest: Let us now build a random forest to predict the species a given iris plant belongs to. Try to go through all the steps and to understand what each step is doing.

Build the random forest model using the Gini index (the library randomForest can only consider Gini as the impurity index), 200 trees, sample of size 60 with replacement, m=sqrt(4)=2 input variables for each question (or split) of the tree:

set.seed(seed)
random_forest=randomForest(data=iris.training,Species~Sepal.Width+Sepal.Length+Petal.Length+Petal.Width,ntree=200,sampsize=60,replace=TRUE,mtry=2)

Here the seed variable controls the internal random generator that is used by the random forest algorithm (for example for selecting data points from the training dataset to make the M bootstrap training subsets or for selecting m=2 features from the p=4 iris features while building the M trees).

Comment: To show all the possible options, you may type help(randomForest) or look at the R documentation: https://cran.r-project.org/web/packages/randomForest/randomForest.pdf

The above confusion matrix and the out-of-bag (OOB) error rate [7/90*100=7.78%] are obtained as follows: for each plant in the training dataset, make a random forest prediction using only the trees that did not use that particular plant in their bootstrap training subset. In the OOB approach, the random forest model is thus used to predict the data NOT drawn (the “out-of-bag” sample).

Let us plot the OOB misclassification error rate as a function of the number of trees used in the random forest:

plot(random_forest)
legend("top",cex=0.8,legend=colnames(random_forest$err.rate),lty=c(1,2,3),col=c(1,2,3),horiz=T)

The x-axis is the “number of trees” and the y-axis is the “OOB misclassification error rates”. The black solid line represents the overall OOB error. The colour lines are the class errors (one for each species: red=Setosa, green=Versicolor and blue=Virginica). We see that we should use about 100 trees (the Random Forest models with less than 100 trees have lower OOB errors but seem rather unstable, so we prefer the stable Random Forest model with about 100 trees):

set.seed(seed)
random_forest=randomForest(data=iris.training,Species~Sepal.Width+Sepal.Length+Petal.Length+Petal.Width,ntree=100,sampsize=60,replace=TRUE,mtry=2)

Comment: The advantage of using the oob accuracy instead of the validation accuracy to determine the best number of trees is that you do not need to keep a validation dataset on the side. If you only use random forests, then you may merge the above training and validation datasets and use oob accuracy (or k-fold cross-validation accuracy) to select the best values for all the hyperparameters. However, in our case, we want to compare the decision tree with the random forest, so we need to use a common separate validation dataset.

BONUS 1 - The classification regions and associated decision boundaries: We will use a home made decision plot funtion written by Michael Hahsler:

decisionplot=function(model,data,class=NULL,predict_type="class",resolution=100,showgrid=TRUE, ...) {

  if(!is.null(class)) cl=data[,class] else cl=1
  data=data[,1:2]
  k=length(unique(cl))

  plot(data,col=as.integer(cl)+1L,pch=as.integer(cl)+1L, ...)

  r=sapply(data,range,na.rm=TRUE)
  xs=seq(r[1,1],r[2,1],length.out=resolution)
  ys=seq(r[1,2],r[2,2],length.out=resolution)
  g=cbind(rep(xs, each=resolution),rep(ys,time=resolution))
  colnames(g)=colnames(r)
  g=as.data.frame(g)

  p=predict(model,g,type=predict_type)
  if(is.list(p)) p=p$class
  p=as.factor(p)

  if(showgrid) points(g,col=as.integer(p)+1L,pch=".")

  z=matrix(as.integer(p),nrow=resolution,byrow=TRUE)
  contour(xs,ys,z,add=TRUE,drawlabels=FALSE,lwd=2,levels=(1:(k-1))+.5)

  invisible(z)
}

BONUS 2 - Let us find the best hyperparameters by using the Grid Search method

Choose the hyperparameters you want to tune, and the corresponding range of values:

hyper=list(maxdepth=1:5,minsplit=1:10,minbucket=1:5)
gs=tidyr::expand_grid(!!!hyper)

Create a function to go through our grid search hyperparameter combinations:

model=function(...) {
  set.seed(seed)
  rpart(data=iris.training,Species~Petal.Length+Petal.Width,method="class",control=rpart.control(...),parms=list(split="information"))
}

Iterate through the values of the hyperparameters and fit the corresponding models:

gs=gs %>% mutate(fit=pmap(gs,model))
validation_features=iris.validation %>% select(-Species)
validation_labels=iris.validation$Species

Create a function to compute the accuracy:

compute_accuracy=function(fit,validation_features,validation_labels) {
  predicted=predict(fit,validation_features,type="class")
  mean(predicted==validation_labels)
}

Compute the validation accuracy of all the tree models considered in the grid search:

gs=gs %>% mutate(validation_accuracy=map_dbl(fit,compute_accuracy,validation_features,validation_labels))

Sort results by high accuracy, more minsplit and less maxdepth:

gs=gs %>% arrange(desc(validation_accuracy),desc(minsplit),maxdepth)
